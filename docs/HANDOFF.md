## 1. 다른 PC에서 시작하기

```sh
git clone https://github.com/HazySound/MoaMoa.git
cd MoaMoa
npm install          # Node 22 (개발 PC는 v22.19.0)
npm run dev          # http://localhost:5174
npm test             # 50여 개 테스트. 캡처(test/fixtures)로 인식까지 검증
npm run check        # svelte-check + tsc
```

배포는 Cloudflare Workers 정적 자산이다 (Pages가 Workers에 합쳐지면서 wrangler가 자동 전환).
**`main`에 푸시하면 자동 배포된다** (2026-10-02부터 Cloudflare 대시보드의 Workers Builds에 GitHub 레포 연결).
그래서 사용자가 "플레이 중"이라고 하면 푸시도 하지 않는다. 손으로 올려야 할 때만 아래를 쓴다.

```sh
npx wrangler login   # 새 PC에서 한 번. 계정: cemigs1@gmail.com
npm run deploy       # vite build → wrangler deploy (wrangler.jsonc가 dist를 올린다)
```

- 배포된 버전은 사이트 맨 아래 `날짜 · 커밋` 글씨로 확인한다

- `@cloudflare/vite-plugin`은 **넣지 않는다.** wrangler가 처음 배포할 때 자동으로 넣는데 vitest를 깨뜨린다
  ("There is already a server associated with the config"). 서버 코드 없는 정적 사이트라 필요 없다.
- `.wrangler/deploy/config.json`이 남아 "redirected configuration path ... does not exist" 오류가 나면 `.wrangler/deploy`를 지운다.
- `https://moamoa.pages.dev`는 남의 사이트다. 우리 주소는 `*.workers.dev`.
- git push는 Git Credential Manager로 된다 (gh CLI 없음).

## 2. 게임 규칙 (공식 안내 + 캡처로 확인)

- 판 10열 × 16행. **줄이 지워져도 위 블록이 내려오지 않는다** (그 줄만 빈다)
- 조각 3개가 한 세트. 셋 다 놓아야 새 세트. 놓는 순서 자유. 회전(시계 방향, GIF로 확인)·좌우 반전 가능
- 점수: 칸 수 + 줄 제거 300×n² (1~5줄: 300/1,200/2,700/4,800/7,500) + 능력 획득 50. 한 판 최대 500,000
- 단계: 제거한 줄 누적 0~30 / 31~60 / 61~100 / 101~150 / 151+. 올라갈수록 작은 조각이 덜 나온다
- 조각 19종: `src/lib/core/pieces.ts` (다른 이용자 정리표에서 모양 데이터를 가져왔고, 캡처로 읽은 조각과 모두 일치)
- 능력
  - 조각을 7번 놓을 때마다(점 찍기는 안 셈) 빈칸 하나에 아이콘. 바꿔 뽑기 60% · 점 찍기 40%
  - **아이콘이 있는 줄을 지워야 획득**. 최대 7개
  - 7개면 획득 못 하고 아이콘이 판에 남는다(회색으로 바뀜). **아이콘이 새로 생기지도 않고 '다음 능력' 카운트도 멈춘다**
  - 판에 아이콘은 최대 3개, 넘치면 가장 오래된 것부터 사라짐
  - 7개면 오른쪽 '보유 능력' 칸이 주황색 '능력이 가득 찼습니다'로 바뀐다
  - 바꿔 뽑기: 버튼 → '바꿀 조각을 골라 주세요'(카드가 보라색) → 카드 클릭 → 그 카드만 새 조각
  - 점 찍기: 버튼 → 판의 칸 클릭 (1칸 채움)
- 조작: 카드를 고르고 판 위에 올리면 초록(가능)/빨간 X(불가) 미리보기, 클릭으로 놓음. 지워질 줄은 하얗게 강조.
  커서는 조각의 `floor((h-1)/2), floor((w-1)/2)` 칸을 잡는다. 판 위 우클릭은 회전
- 메이플 커서(흰 손)가 화면에 그려진다

스크린샷/                 사용자가 준 원본 캡처·공식 안내 이미지

## 4. 인식·추적이 어떻게 동작하나 (그리고 왜)

### 인식 (vision/read.ts)
- 판 위치: 빈 칸 사이 격자선(양옆보다 조금 어두운 청록)의 열·행 봉우리가 같은 간격으로 11·17개 늘어선 자리.
  한 칸 밀린 자리와 헷갈려서, 오른쪽 '보유 조각' 카드 세 장이 제자리에 있는지로 최종 결정(settle)
- 칸 상태: 테두리 링(22%) + 가운데 촘촘히 + 가장자리(8%)
  - empty / block / hover(초록 미리보기) / invalid(빨간 X) / flash(지워질 줄) / cursor / unknown
  - 아이콘: `icon-swap`(보라), `icon-dot`(흰 동심원), 밑이 블록이면 `-on`. 밑은 underOf가 정한다: 가장자리 20점의
    (255-R, 255-G, 255-B) 비율 — 흰색과 섞여도(반짝임) 안 변한다. 밝기·채도 기준으로 되돌리지 말 것
  - 커서: 짙은 회색 외곽선 (가운데 또는 칸 전체에서). 흰 손이 점 찍기 아이콘처럼 하얗다
- 카드: 바탕(흰/노랑=선택/하늘=사용 완료) 대비 다른 픽셀, 미리보기 칸 = 판 칸의 1/3
- 수치(캡처에서 잰 값)는 코드 주석에 있다

### 추적 (engine.svelte.ts) — 버그가 가장 많이 났던 곳
- **추천은 세트(카드 3장)를 처음 볼 때 한 번 계산하고 고정**한다. 판이 흔들려도 다시 계산하지 않는다
- 판이 바뀌면 **손의 조각 하나(또는 점 찍기 1칸)를 놓은 결과와 정확히 같은지**로만 받아들인다(explainMove).
  커서·아이콘 칸·미리보기 칸은 '모름'(와일드카드)으로 두고 기억한 값을 쓴다
- 추천대로 놓으면 단계만 넘기고, 다르게 놓으면 남은 조각으로 다시 계산
- 판은 그대로인데 카드가 '사용 완료' → 안 보이는 칸(아이콘 칸 등)에 놓은 것 → placeHidden
- 이미 놓은 카드 자리에 새 조각 → 새 세트. 아직 안 놓은 카드가 다른 조각이 되면 → 바꿔 뽑기
- 설명 안 되는 판이 1.5초, 카드가 기억과 다른 게 2초 이어지면 화면 기준으로 다시 맞춤(resync)
- 아이콘: 연달아 2번 보이면 인정. 없어지는 건 그 줄이 지워질 때 / 넷째가 생길 때 / 5초 내내 빈칸일 때만.
  새 아이콘은 놓은 직후(3초)나 7번째 배치 뒤 차례(spawnPending)에만 받는다(커서 오인 방지)
- 같은 상황은 다시 계산하지 않고 저장된 결과를 쓴다(solveCache). 되풀이 루프 안전장치
- '최근 기록'(events)에 계산 이유·능력 획득/사용·다시 맞춤을 남긴다 → '인식 화면 보기'에서 확인

### 추천 (core/solver.ts)
- 빔 탐색(기본 폭 160)으로 순서 × 회전·반전 × 위치 → 상위 후보 10개를 남은 시간(기본 1.5초) 동안
  다음 세트를 같은 표본으로 가상 플레이해 고른다. 같은 판이면 같은 표본이라 언제나 같은 답
- 빠른 평가 `W`: 줄 채움², 줄 안 빈칸 토막, 세로 엇갈림, 찬 칸 수, 1·2칸 구멍, 막다른 칸 (+실험용 항목들)
- 능력 `ADV`: 바꿔 뽑기는 막혔을 때만(더 값지다). 점 찍기는 막혔을 때 또는 큰 이득(못 메우는 칸).
  **6개 이상이면 이득이 될 때 점 찍기부터 털어 회전**(7개면 공급이 끊긴다)

## 5. 겪은 문제와 해결 (시간순)

| 증상 | 원인 | 해결 |
|---|---|---|
| 판 위치가 한 칸 밀림 | 격자선 간격만으론 구분 안 됨 | 카드 위치로 검증(settle) |
| 분홍 블록을 바꿔 뽑기 아이콘으로 | 보라 판정이 넓음 | B > R+12 조건 |
| 추천이 계속 바뀜, 놓아도 멈춤 | 매 프레임 화면 전체가 같아야 확정 → 반짝임에 막힘 | 세트 고정 + 배치로 풀릴 때만 따라감 |
| 아이템 칸에 놓은 블록을 빈칸으로 | 아이콘은 블록 위에도 그려짐 | 가장자리로 밑 판별, 이후 아이콘 칸은 와일드카드 |
| 커서를 점 찍기 아이콘으로 | 흰 손 | 외곽선 검사(칸 전체) + 놓은 직후에만 새 아이콘 |
| '점 찍기 → 다시 맞춤' 무한 반복 | 블록 위 아이콘이 블록/빈칸으로 오락가락 | 아이콘 칸 와일드카드, 점 찍기는 보유 시만 후보, 계산 캐시 |
| 1칸 조각을 아이콘 칸에 넣으면 멈춤 | 판 변화가 안 보임 | 카드 '사용 완료'로 알아채기(placeHidden) |
| 같은 조각 두 장일 때 재계산 | 카드 번호 다름 | 같은 자리면 따른 것으로 보고 번호 맞바꿈 |
| 새 세트 직후 바로 놓으면 지난 카드 기억 | '셋 다 새것'을 못 봄 | 카드-기억 불일치 2초면 다시 맞춤 |
| '다음 능력'이 자꾸 7로 | 반짝임으로 아이콘을 지웠다 다시 보면 새것으로 | 아이콘은 줄 지울 때만 없어짐 |
| 아이콘 터뜨리기 전에 능력 +1 | 줄 지운 직후 그 빈 줄에 새로 생긴 아이콘을 획득으로 | 판 바뀌기 전부터 있던 아이콘만 획득 |
| 7개일 때 아이콘 지움 | 규칙 오해 | 7개면 남김, 카운트 멈춤 |
| 미리보기 중 아이콘 못 봄 | busy 프레임에서 추적까지 건너뜀 | 미리보기 중에도 아이콘 추적, spawnPending |
| **능력 획득이 자주 빠짐** | '방금 생김' 표시를 줄 지운 배치에서만 풀었음 | 모든 배치 뒤에 품 (558f922) |
| PiP에서 설정 못 함 | — | PipControls (±, 성향, 계산 시간) |
| '다음 능력'이 엉뚱하게 7로 초기화 | 놓은 직후 커서를 새 아이콘으로 보면 7로 보정 | 카운트를 알면 보정 안 함 (`?`일 때만) |
| 커서를 아이콘으로 받음 | 아무 배치 뒤 3초 안이면 받았음 | 카운트를 알면 7번째 배치 뒤(spawnPending)·빈칸·한 개만 받음 |
| 바꿔 뽑기 안 썼는데 개수 감소 | 카드 오독(커서·덜 그려진 새 세트)을 사용으로 셈 | 보라 카드(고르는 화면)를 본 뒤에만 사용. 모양만 다르면 카드만 다시 읽음(카운트 유지) |
| 블록 위 아이콘 칸을 빈칸으로 앎 (막힌 칸에 놓으라고 추천) | 아이콘 밑 판별이 가장자리 채도 기준이었는데, 아이콘이 반짝여 칸이 20%만 밝아져도 뒤집혔다. 캡처 한 장에서는 맞아도 실제 화면에서는 계속 틀림 | 흰색과 섞여도 안 변하는 색 비율로 판별(vision underOf). 아이콘 칸 19개·일반 칸 2,057개, 밝기 0~80%에서 오답 없음. 엔진은 이 값으로 기억을 0.6초 안에 바로잡고, 아이콘이 있는 칸은 늘 '모름'으로 둔다 |
| 세트 중간에 능력이 6~7개가 돼도 쓰라는 안내가 없음 | 능력 안내는 추천 계산 때만 같이 계산(세트당 한 번) | 화면 숫자로 능력이 늘어 6개 이상이 되면 남은 조각으로 다시 계산 |
| 새로고침 뒤 판에 있던 아이콘을 못 받음 | 카운트를 알면 7번째 배치 뒤에만 받게 해서 | 다른 칸에 놓는 동안에도 같은 칸에 그대로면 받음(lingering) |
| 마우스를 판에 대고 있으면 다시 맞춤 → 카운트 초기화·커서를 아이콘으로 | 한 칸 오독을 1칸 조각 배치로 설명, 설명 안 되면 1.5초 뒤 다시 맞춤(카운트 '모름') | 카드가 그대로 보이면 배치 아님. 카드가 다 그대로면 8초 뒤에만, 카운트 유지한 채 다시 맞춤 |

남은 알려진 한계
- **능력 개수는 게임 화면 숫자가 정한다 (2026-10-03, vision/digits.ts + core/counts.ts).** 따라 세기만으로는 커서 오독
  하나로 개수가 틀어지고 못 되돌려서, 사용자 동의를 받고 바꿨다. 네 자리를 본다: 점 찍기·바꿔 뽑기 버튼 숫자(배지),
  '다음 능력 N번', '보유 N/7'
  - 숫자는 **획 구조로 짐작**한다 (guessDigit: 폭, 아랫줄, 가운데 줄, 왼쪽·오른쪽 세로획). 캡처 표본 54개(두 글꼴,
    칸 36.6px·48.8px)에서 전부 맞고, 0.8~2배로 늘리고 줄여도 맞는다 (test/digits.test.ts)
  - 버튼 숫자는 **표본 대조로 못 읽는다.** 배지 글꼴은 같은 숫자도 화면 크기·자리에 따라 4.5까지 다르게 그려지고
    (다른 숫자와는 5.9), 4·5·7은 캡처가 없다. 첫 판(표본 대조)은 큰 화면에서 버튼 2·3만 읽혔고, 못 읽으면 2초 뒤
    따라 세기로 돌아가서 보유가 많을 때 개수가 혼자 틀어졌다. 판넬 글꼴은 표본 대조가 통해서 짐작과 같이 쓴다
  - **검산: 점 찍기 + 바꿔 뽑기 = 보유** (꽉 차면 7). 맞으면 받아들이고 그 모양을 기억한다(브라우저 저장, moamoa.shapes.v1).
    안 맞으면 '누가 틀렸나'를 가정별로 따져 덜 믿는 하나를 나머지 둘로 계산한다(기록에 '합으로 알아냄').
    못 정하면 값을 그대로 두고 작은 창에 `?`만 띄운다(기록에 '화면 숫자 못 정함' + 모양 그림)
  - **숫자를 한 번이라도 읽은 뒤에는 따라 세기가 개수를 바꾸지 않는다** (numsSeen). 점 찍기·바꿔 뽑기 '사용'도
    화면 숫자가 실제로 줄었을 때만 받는다 (canUse)
  - 기록의 모양 그림('8x11:3c.66…')은 줄마다 16진수 비트다. 짐작이 틀리는 모양이 나오면 이걸로 guessDigit을 고친다
- 최근 기록은 새로고침해도 남는다 (moamoa.events.v1, 400개)
- 게임 화면 위에 직접 겹쳐 표시(투명 오버레이)는 웹으론 불가. 데스크톱(Electron) 앱이면 되지만 사용자가 원치 않음

## 6. 가상 플레이 실험 결과 (test/simlib.ts)

모두 같은 씨앗의 게임으로 비교. 'n=30'은 10판×3묶음 평균.

| 실험 | 평균 생존 세트 | 평균 점수 |
|---|---|---|
| 첫 엔진 (빠른 계산, 능력 막혔을 때만) | 47 | 27,000 |
| + 다음 세트 가상 플레이 1.5초 (앱 설정) | 70 | 51,500 |
| 작은 조각(≤5칸) 2배 가정 | 104 | 60,600 |
| 작은 조각 3배 가정 | 149 | 84,300 |
| 우물(연속 제거) 항목, 우물 전용 열 | 이득 없음 / 오히려 나빠짐 | |
| 능력: 막혔을 때만 (n=30) | 52.2 | 31,000 |
| 능력: 7개부터 털기 | 58.5 | 35,800 |
| 능력: **6개부터 털기 (채택)** | 59.0 | 36,600 |
| 능력: 5개부터 털기 | 54.1 | 33,100 |

- 평가 가중치 `W` 흔들기 튜닝은 기본값을 못 넘었다 (구멍 벌점 키우기, 3×3 빈 공간 등)
- 3줄 이상 연속 제거는 고른 확률에선 거의 안 생긴다 (한 열 우물을 채우는 조각이 ㅣ·ㅡ뿐)
- 50만 점은 세트당 약 3,000점(5줄 연속 위주)이면 170세트, 한 줄씩이면 830세트가 필요

### 실제 조각 빈도 (docs/data/piece-stats-2026-10-03.json, 두 PC 합산 870개)
단계별 표본 219 / 114 / 81 / 87 / 369. 5칸 이하 비율 1단계 64% → 5단계 36%, 평균 칸 수 4.5 → 6.2.
5단계 상위: ㅌ 13%, ㄷ 9%, ㄹ 9%, ㅊ 8%, ㅏ 8%. 세로로 꽂는 ㅣ·ㅡ·점은 합쳐 12%뿐이라 후반에는 한 열 우물(ㅣ로 5줄)이 비현실적이다.
가상 플레이는 `REAL=1`로 이 빈도를 쓴다 (simlib weightsFor).

사용자 실제 기록: 2026-10-03 새벽 **16만 점** 판 (215세트, 664조각, 1줄 276 · 2줄 48 · 3줄 3). 세트당 725점.
2줄 제거는 횟수 15%로 점수 37%를 냈다. 기본 추천은 2줄 이상이 9%뿐이라 큰 단위 제거 항목(W.near2·near3·single·potential)을 넣었다.

## 7. 다음에 할 일

1. **실제 빈도로 가상 플레이 보정**: `simlib.ts`의 `drawPiece`가 docs/data의 빈도(또는 blendedWeights)를 쓰게 하고
   기준선을 다시 잰다. 2·3단계 표본이 더 모이면 단계별로
2. 보정된 가상 플레이로 `W`·`ADV` 다시 고르기. 하나씩 흔들기는 실패했으니 교차 엔트로피(CEM)로,
   목표는 생존 세트가 아니라 **점수**. 연속 제거 항목(well/align)도 실제 빈도에선 다시 볼 가치가 있다
3. 고득점 모드(세트당 5~10초, 다음 2세트까지)는 사용자가 확률 통계가 먼저라고 해서 보류 중
4. 판 기록 점수가 게임 화면 점수와 맞는지 사용자 확인 필요

## 8. 사용자 선호 (작업 방식)

- 한국어. 코드 주석도 한국어로 '왜'를 적는다 (MapleMVP와 같은 결)
- 끝까지 직접 진행: 수정 → 테스트 → 커밋 → 푸시 → 배포. 인증 같은 것만 사용자에게
- **플레이 중이라고 하면 푸시·배포하지 말 것** (로컬 커밋만)
- 추측으로 원인을 단정하지 말 것. 코드와 데이터로 확인하고 말한다
- **영어 금지.** 최종 답변뿐 아니라 작업 중간 설명·진행 상황까지 전부 한국어로
- 데스크톱 앱은 원치 않음. 화면 숫자는 정해진 자리의 모양 맞추기로만 읽는다(일반 OCR 아님)
- 기억한 걸 화면에서 한 번 못 찾았다고 바로 다 날리지 말 것 (다시 맞춤은 최후 수단)
- 작은 창(PiP)에서 모든 걸 볼 수 있어야 한다 (게임만 보면서 플레이)
- 능력: 바꿔 뽑기가 더 값지다. 막혔을 때만 쓰고, 꽉 차면 점 찍기부터 턴다
